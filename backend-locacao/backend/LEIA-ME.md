# Backend de locação de tendas e banheiros químicos

Adaptação da plataforma de logística. Tudo o que já existia continua funcionando.

## Como instalar

1. Substitua os arquivos pelos deste pacote.
2. Rode `npm install` (entrou a dependência `express-async-errors`).
3. No Railway, confira se a variável `JWT_SECRET` está definida. Sem ela, o sistema usa uma senha padrão, que é insegura.
4. Suba normalmente. O `schema.sql` roda sozinho ao iniciar e cria as tabelas novas.

## Fluxo de uma locação

1. **Orçamento**: `POST /api/rentals`. Não reserva estoque, mas já avisa em `shortages` se faltar algo.
2. **Confirmação**: `POST /api/rentals/:id/confirm { teamId }`. Reserva o estoque e gera as O.S.:
   entrega/montagem no primeiro dia, limpezas a cada N dias (conforme o produto) e retirada/desmontagem no último dia.
3. **Entrega em campo**: a equipe conclui a O.S. informando os códigos das unidades (`BQ-001`...). A locação vira `em_andamento`.
4. **Retirada**: a equipe informa os códigos e o estado de cada um. As unidades vão para `higienizacao` (ou `manutencao` se danificadas).
   Quando a última retirada é feita e tudo voltou, a locação vira `encerrado` sozinha.
5. **Pátio**: depois de lavar, o escritório marca a unidade como `disponivel` em `PUT /api/assets/:id/status`.

## Endpoints novos (painel, exigem login)

**Produtos** `/api/product-types`
- `GET /` (`?all=1` inclui desativados) · `POST /` · `PUT /:id` · `DELETE /:id`
- Campos: `category` (tenda | banheiro | acessorio), `name`, `dailyPrice`, `cleaningIntervalDays`, `turnaroundDays`, `setupMinutes`, `teardownMinutes`, `active`

**Unidades** `/api/assets`
- `GET /?productTypeId=&status=&code=` · `GET /summary` (contagem por status para o painel)
- `POST /` · `POST /bulk { productTypeId, prefix, count, startNumber, digits }` → cria BQ-001, BQ-002...
- `PUT /:id` · `PUT /:id/status { status, notes }` · `GET /:id/history` · `DELETE /:id`

**Locais** `/api/sites`
- `GET /?clientId=` · `POST /` · `PUT /:id` · `DELETE /:id`

**Locações** `/api/rentals`
- `GET /?status=confirmado,em_andamento&from=&to=&clientId=`
- `GET /availability?start=&end=&excludeRentalId=`
- `GET /:id` (inclui unidades alocadas e O.S.)
- `POST /` · `PUT /:id` (se confirmada, revalida estoque e refaz as O.S. pendentes)
- `POST /:id/confirm { teamId }` · `POST /:id/cancel { reason }`
- `POST /:id/close { missingAssetsStatus }` (encerramento manual quando sobra unidade no local)
- `DELETE /:id` (só orçamentos ou canceladas)

**O.S.** `/api/appointments` (novidades)
- `GET` aceita `?from=&to=&teamId=&rentalId=`
- Campos novos: `rentalId`, `siteId`, `kind`, `timeWindow`, `routeOrder`, `items`, `autoGenerated`
- `PUT /route/order { order: [ids] }` para reordenar a rota do dia

## App da equipe `/api/team-app` (novidades)

- `GET /appointments` agora traz `kind`, `items`, `site`, `location` e `rental.assetsAtSite`.
  **O mapa e o botão de navegação devem usar `location`**, que é o endereço do evento (e cai para o do cliente se não houver local).
- `POST /appointments/:id/complete` aceita também:
  `assets: [{ code, condition, notes }]`, `signature`, `signedBy`, `lat`, `lon`.
  A resposta traz `warnings` (ex.: código não cadastrado) para mostrar à equipe.
- `POST /appointments/:id/start` → marca `em_rota`
- `POST /appointments/:id/fail { reason }` → marca `nao_realizado`
- `GET /assets/:code` → valida um código enquanto a equipe digita

## Configuração opcional

Tarefas padrão por tipo de visita (ex.: toda limpeza já vem com sucção, higienização e reposição de papel):

```
PUT /api/settings/default_tasks_by_kind
{ "value": { "limpeza": ["idTarefaSuccao", "idTarefaHigienizacao"] } }
```

## Regras de negócio que você pode querer ajustar

- **Preço**: `unitPrice` é a diária por unidade, e os dias contam da entrega à retirada, incluindo as duas datas. Para cobrar por evento, envie `totalValue` direto.
- **Turnaround**: cada produto fica bloqueado `turnaroundDays` dias depois de voltar, para lavagem.
- **Limpezas**: se houver banheiros com intervalos diferentes na mesma locação, vale o menor.
- **Unidades em manutenção** não contam como estoque disponível.
